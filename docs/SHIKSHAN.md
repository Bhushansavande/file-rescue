# डेटा रिकव्हरी: शिक्षण (सुरुवातीपासून)

## 1. फाइल डिलीट केल्यावर प्रत्यक्षात काय होते?

तुमचा ड्राइव्ह म्हणजे एक मोठे पुस्तक आहे असे समजा:

- **डेटा** = पुस्तकातील पाने (फोटो, गाण्याचे प्रत्यक्ष बाइट्स).
- **फाइल सिस्टम (NTFS, FAT32, exFAT, ext4)** = पुस्तकाची अनुक्रमणिका (index): कोणती फाइल कोणत्या पानांवर आहे.

फाइल **डिलीट** केल्यावर सहसा फक्त अनुक्रमणिकेतील नोंद काढली जाते आणि ती पाने "रिकामी, पुन्हा वापरता येतील" म्हणून चिन्हांकित होतात. पानांवरचा मजकूर तसाच राहतो, जोपर्यंत तिथे **नवीन फाइल लिहिली जात नाही**. म्हणूनच रिकव्हरी शक्य होते.

म्हणून पहिला नियम: **डिलीट झाल्यानंतर त्या ड्राइव्हवर काहीही लिहू नका** (डाउनलोड, फोटो काढणे, ॲप इन्स्टॉल, WhatsApp मीडिया, सगळेच).

## 2. रिकव्हरीचे तीन मार्ग

| मार्ग | कसे चालते | नाव/फोल्डर मिळते? | यश |
|---|---|---|---|
| **Recycle Bin / ट्रॅश** | फाइल अजून जशीच्या तशी आहे, फक्त हलवली आहे | होय | सर्वोत्तम |
| **फाइल सिस्टम रिकव्हरी** (TestDisk, Recuva) | अनुक्रमणिकेतील जुनी नोंद शोधते | बहुतेक वेळा | चांगले |
| **File carving** (हा प्रोजेक्ट, PhotoRec) | अनुक्रमणिका वापरतच नाही; डेटामध्ये फाइलची सुरुवातीची खूण शोधते | नाही (नावे नवीन देतात) | डेटा पुसला नसेल तर चांगले |

### File carving कसे चालते?

प्रत्येक फाइल प्रकाराच्या सुरुवातीला एक ठराविक खूण (**magic number / header**) असते:

| प्रकार | सुरुवातीचे बाइट्स |
|---|---|
| JPEG | `FF D8 FF` |
| PNG | `89 50 4E 47 0D 0A 1A 0A` |
| PDF | `%PDF-` |
| ZIP / APK / DOCX | `50 4B 03 04` ("PK") |
| MP4 | 4 बाइट्सनंतर `ftyp` |
| MP3 | `ID3` |

टूल संपूर्ण ड्राइव्ह वाचत जाते, अशा खुणा शोधते, आणि मग **शेवट कुठे ते मोजते**:

- JPEG: फाइलमधील मार्कर्स एकामागून एक वाचून खरा शेवट शोधते (थंबनेलमधील खोट्या शेवटाला फसत नाही).
- PNG/PDF: ठराविक शेवटची खूण (`IEND`, `%%EOF`).
- MP4: फाइलमधील "बॉक्सेस" ची लांबी जोडत जाते.
- MP3: गाण्याचे फ्रेम्स मोजते.
- APK: ZIP चा शेवटचा भाग (End of Central Directory) शोधते, मग आत `AndroidManifest.xml` असेल तर तिला `.apk` नाव देते.

फाइल्स साधारणतः ड्राइव्हवर **512 बाइट्सच्या सीमेवर** सुरू होतात, म्हणून टूल फक्त तशाच जागा तपासते (`--no-align` ने बंद करता येते). यामुळे चुकीचे हिट्स खूप कमी होतात.

## 3. TRIM आणि एन्क्रिप्शन: मोठा अडथळा

- **SSD / फ्लॅश + TRIM:** डिलीटनंतर OS ड्राइव्हला सांगतो "हे ब्लॉक्स आता वापरात नाहीत" आणि ड्राइव्ह ते लवकरच (सेकंद-मिनिटांत) खरोखर पुसतो. अशा वेळी रिकव्हरी जवळजवळ अशक्य असते. **HDD** (फिरणारी डिस्क) वर संधी जास्त असते.
- **फोनची अंतर्गत स्टोरेज:** आधुनिक Android फोन्समध्ये ती **एन्क्रिप्टेड** असते आणि TRIM चालू असतो. त्यामुळे लॅपटॉपवरील कोणतेही टूल (मोफत किंवा पैसे देऊन घेतलेले) root शिवाय आणि बहुतेक वेळा root सोबतही डिलीट फोटो परत आणू शकत नाही. "एका क्लिकमध्ये फोन रिकव्हरी" अशा जाहिराती फसव्या असू शकतात.
- **SD कार्ड, पेन ड्राइव्ह:** सहसा एन्क्रिप्टेड नसतात आणि TRIM कमी असतो. इथे carving सर्वात चांगले चालते.

## 4. फोनमधून फाइल्स परत मिळवण्याचे खरे मार्ग (प्राधान्य क्रमाने)

1. **गॅलरीतील "Recently deleted / Trash / Recycle bin":** Google Photos (60 दिवस), Samsung Gallery (30 दिवस), Xiaomi Gallery, इत्यादी. ही पहिली गोष्ट तपासा.
2. **Google Photos / Drive बॅकअप:** photos.google.com वर तपासा. तिथे Trash सुद्धा आहे.
3. **`.trashed-` फाइल्स (हे टूल):** Android 11+ मध्ये `filerescue android` ने काढा.
4. **WhatsApp:** चॅट बॅकअप रिस्टोअर करा; किंवा तोच मीडिया `Android/media/com.whatsapp/WhatsApp/Media` मध्ये असू शकतो.
5. **फोनचा SD कार्ड:** कार्ड रीडरने लॅपटॉपला जोडा आणि `filerescue carve` चालवा.
6. **ॲपचे APK:** Play Store वरून पुन्हा डाउनलोड करा; जुनी आवृत्ती हवी असल्यास स्वतःचे बॅकअप किंवा विश्वासार्ह आर्काइव्ह. तुमच्या स्वतःच्या ॲपचा APK असेल तर तो बिल्ड फोल्डर/Git मधून पुन्हा बनवता येतो.
7. **लॅपटॉपवर आधी कॉपी केलेले असू शकते:** जुन्या USB ट्रान्सफर, ईमेल, क्लाउड, मेसेंजर "Saved" फोल्डर्स तपासा.

## 5. लॅपटॉपमधून परत मिळवण्याचे टप्पे

1. **ताबडतोब वापर थांबवा** (शक्य असल्यास कॉम्प्युटर बंद करा).
2. **Recycle Bin** तपासा: `filerescue recyclebin`.
3. **OneDrive / Google Drive** चे ट्रॅश आणि "File History / Previous Versions" (फोल्डर → Properties → Previous Versions) तपासा.
4. शक्य असल्यास ड्राइव्ह दुसऱ्या कॉम्प्युटरला जोडा, किंवा **इमेज बनवा**: `filerescue image`.
5. **वेगळ्या ड्राइव्हवर** आउटपुट घेऊन `filerescue carve` चालवा.
6. गरज पडल्यास **PhotoRec / TestDisk** वापरा (मोफत, ओपन-सोर्स, सिद्ध).

## 6. इतर मोफत/ओपन-सोर्स टूल्स (तुलना आणि शिकण्यासाठी)

| टूल | वैशिष्ट्य |
|---|---|
| **PhotoRec / TestDisk** (cgsecurity.org) | कार्विंगचा "सुवर्ण मानक", 480+ प्रकार, Windows/Linux/Mac |
| **ddrescue** | खराब होत असलेल्या ड्राइव्हची इमेज बनवण्यासाठी सर्वोत्तम |
| **The Sleuth Kit / Autopsy** | फॉरेन्सिक विश्लेषण, फाइल सिस्टम खोलवर |
| **scalpel / foremost** | जुनी पण सोपी carving टूल्स |
| **adb (platform-tools)** | Android डिव्हाइसशी संवाद |

या प्रोजेक्टचा उद्देश: मराठीत शिकता येईल, वाचता येईल असा सोपा Python कोड आणि मार्गदर्शन, जेणेकरून तुम्ही स्वतः समजून पुढे वाढवू शकाल.

## 7. सुरक्षितता आणि कायदा

- फक्त **तुमच्या स्वतःच्या** किंवा स्पष्ट परवानगी असलेल्या डिव्हाइसवर वापरा. दुसऱ्याच्या फोन/लॅपटॉपमधील डेटा त्यांच्या संमतीशिवाय काढणे कायद्याने गुन्हा आहे.
- रिकव्हर केलेल्या फाइल्समध्ये खाजगी माहिती असते. त्या सुरक्षित ठेवा; या repo मध्ये किंवा सार्वजनिक ठिकाणी अपलोड करू नका (`.gitignore` ने तसे अडवले आहे).
- रिकव्हर केलेले APK **चालवण्यापूर्वी** तपासा. ते कोणाचे आहे, कुठून आले हे अनिश्चित असेल तर इन्स्टॉल करू नका.

## 8. स्वतःला तपासा

1. फाइल डिलीट केल्यावर डेटा लगेच पुसला जातो का? (नाही, सहसा फक्त नोंद काढली जाते.)
2. SSD वर रिकव्हरी कठीण का? (TRIM)
3. Carving मध्ये फाइलचे मूळ नाव का मिळत नाही? (नाव अनुक्रमणिकेत असते, डेटामध्ये नाही.)
4. रिकव्हरीनंतर फाइल्स त्याच ड्राइव्हवर का सेव्ह करू नयेत? (त्या अजून न मिळालेल्या डिलीट डेटावर लिहिल्या जाऊ शकतात.)
